# Coding rules — как НЕ писать код в этом проекте

Рабочий список запретов, собранный из реальных находок и внешних
аудитов ИИ-почерка. Проверять при каждом ревью. Один признак —
совпадение, четыре+ — паттерн.

---

## 1. Слои — кто что знает (нарушение = баг архитектуры)

**Backend:**
- `CollabCanvas.Core` — чистый: модель, протокол, комната, журнал-
  контракты. **Ноль** ссылок на Redis/AspNet — проверено grep'ом.
  Запрещено: DI, HTTP, конкретные хранилища.
- `CollabCanvas.Api` — транспорт и хранилища: хабы, Redis-реализации
  контрактов, auth-сторы, эндпоинты.
- `Program.cs` — только регистрация DI + тонкие лямбды эндпоинтов.
  Логика роли/доступа → `CallerRole`/store'ы. Если лямбда
  разрастается логикой — логика уходит в store, не в файл.

**Frontend (DAG без циклов, проверен импорт-графом):**
- `model.ts` — LWW-док. Ничего не знает о проводе и канвасе.
- `session.ts` — провод (SignalR, pending, rejoin, blobUrl). Не знает
  канвас.
- `renderer.ts` — канвас. Получает колбэки, не импортирует session.
- `editor.ts` — жесты → опы через session. Единственный, кто знает
  оба мира — по дизайну.
- `quadtree.ts`/`geometry.ts` — чистая геометрия, type-only импорты.
- `App.tsx` — только wiring: state, effects, JSX. Бизнес-логика —
  в модули, не в компонент.

**Запрещено:** импорт «назад» по графу, type-only там, где значение
не нужно — ок, реальный импорт — нет.

## 2. Auth-fetch правило (класс уже 3 раза ловили живьём)

Любой `fetch` к защищённому пути — **только через `authedFetch`**.
Голый `fetch` на `/docs`, `/ops`, `/blobs`, `/auth/logout` — баг:
юзер теряет права/данные молча. Link-гость: `?grant=` в query.
Исторические жертвы правила: unlist DELETE, refreshDocs, showHistory.

## 3. ИИ-почерк — запрещённые паттерны

- **Коммент-нарратив:** `// set x to y` над `x = y`. Коммент пишет
  ПОЧЕМУ/риск/край — не ЧТО. Исключение — `T-NN:` теги привязки
  к тикету (наша конвенция трассировки).
- **Чужие иероглифы:** вьетнамский уже был в tasks.md/CHANGELOG —
  язык доков единый (рус, код — англ).
- **Копипаст ×3+:** одинаковый сниппет трижды без хелпера.
  `getElementById(...) as T` был ×9 → `field<T>(id)`.
- **Каст-костыли:** `as any`, `as unknown as X` — запрещены.
  `!` после проверенных инвариантов — ок (`noUncheckedIndexedAccess`).
- **Хедеры вручную** рядом с существующей обёрткой.
- **Пустые useEffect**, `useState<string>('')` для выводимых типов,
  `useMemo/useCallback` «на всякий случай» без потребителя.
- **Церемонный try/catch** вокруг кода, который не бросает;
  `.catch(() => {})` без комментария-почему.
- **Генерические имена:** `data`, `result`, `handler`, `manager`,
  `temp`, `item` — если имя не несёт домен.
- **JSDoc/XML-doc на ровном месте** — док на каждый приватный метод
  без добавленного смысла.
- **Хак-фикс вместо корня:** удалить проверку, пин версии, скрыть
  симптом. Нашёл — чинишь причину или честно пишешь край.
- **«Унифицированная свежесть»:** файл «взрослый» целиком в одном
  коммите — история должна быть инкрементальной.

## 4. Консистентность

- `type` (не `interface`) для доменных типов — текущая конвенция.
- camelCase TS / PascalCase C# — без микса в одном файле.
- Тесты только реальные: xUnit ассерты поведения, бот проверяет
  провод и доступы. `Assert.True(true)` — запрещён.
- Нет `console.log`/`dbg` в проде (бот — харнесс, исключение).

## 5. Что считается «сделано»

Не «скомпилилось» и не «зелёный тест» — **поведение проверено
живьём**: бот гоняет реальные сокеты и HTTP, края честно
записываются в тикет. Коммит без прогона — красный флаг.
