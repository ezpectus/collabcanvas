# PLAN — журнал решений CollabCanvas

Каждая нетривиальная дизайн-развилка — строка в журнале: что
решили, варианты, почему. Пишет Devin, юзер оспаривает.

| Дата | Решение | Варианты и причина выбора |
| --- | --- | --- |
| 2026-11-07 | Модель синхронизации: упрощённый CRDT — LWW-регистр на свойство объекта, порядок задаёт центральный сервер (seq). НЕ OT, НЕ полный CRDT. | По образцу реальной Figma: центральный сервер уже видит все записи → timestamp/векторные часы избыточны; «last» = последний дошедший до сервера. OT не нужен — нет инвариантов трансформации текста. Полный CRDT — избыточен, т.к. нет peer-to-peer merge без сервера |
| 2026-11-07 | Порядок детей (z-order/tree order) — fractional indexing (дроби между соседями), НЕ float64 | По образцу Figma: среднее между ключами; float64 исчерпывается после ~50 вставок на одно место → строка/дробь без потери точности |
| 2026-11-07 | Разделение каналов: ops (персистентные, журнал) vs presence (эфемерный, TTL) | Presence в журнале = мусор и раздувание replay; курсор живёт секунды — ему нужен heartbeat+expiry, не durable log |
| 2026-11-07 | Комната = упорядоченный op-стрим на документ; состояние в памяти + журнал + снапшоты | Figma-модель: один процесс-владелец на документ → точка упорядочивания бесплатная. Scale-out (pub/sub) — отдельной стадией T-10, там своя точка |
| 2026-11-07 | Backend — .NET (net8.0 сейчас; net10 при установке SDK). SignalR для WS | Юзер уже знает стек из Notification Engine — ревью на знакомом языке честнее. Node.js-альтернатива из спеки отклонена: фронт и так TS |
| 2026-11-07 | Гранулярность op = per-property `patch` (LWW по seq на каждое свойство) | Альтернативы: целый объект (грубо, конфликты сливают всё) и intent-ops `moveBy` (сохраняют намерение, но нужна семантика на каждый intent). Известный артефакт — franken-merge (x от A + w от B), принят как у Figma (§12.1) |
| 2026-11-07 | Журнал = Redis Stream `doc:{id}:ops` + снапшот `doc:{id}:snap` (каждые K ops или T сек) | Redis уже в стеке; AOF everysec ≈ ≤1с потерь — совпадает с целью Figma. PG append-таблица — строже, но новой зависимости ради MVP не стоит |
| 2026-11-07 | Идемпотентность клиентских ретраев — `clientId + clientSeq` на каждом op | Сервер dedup'ит повторный submit; клиентский offline-buffer шлёт pending заново после reconnect'а |
| 2026-11-07 | Рендер — Canvas 2D + dirty regions + viewport culling; hit-test — QuadTree | SVG DOM мёртв на 10k нод; WebGL — оверкилл до 100k+. QuadTree — динамичен и прост для точек/прямоугольников |
| 2026-11-07 | Текст — LWW целой строкой (ограничение MVP) | Посимвольный co-text требует OT/RGA (Yjs) — выносится в stretch; franken-случай задокументирован |
| 2026-11-07 | Офлайн-правки: pending-очередь + rebase как новые ops после reconnect | Полный локальный merge — это уже полноценный CRDT; MVP принимает «rebase + LWW по серверному seq» |
| 2026-11-08 | Разделение проектов: `Core` = чистые контракты (zero deps), `Api` = транспорт/хабы/инфра | Тесты протокола без подъёма ASP.NET; Core не тянет SignalR/Redis в апстрим-потребителей |
| 2026-11-08 | `SubmitOp` в стабе отвечает `accepted:false "not-implemented"`, а не молчит | Проверка протокола end-to-end уже сейчас; молчаливый приём = ложный успех — хуже честного отказа |
| 2026-11-08 | `/health` ping'ует Redis и отвечает `degraded` 503, но API живёт | Redis — журнал (T-5); без него realtime работает, персистентность деградирует. Статус в теле, не в коде смерти |
| 2026-11-08 | Порты compose: redis→6380, api→8090, web→3100 | 6379/8080 заняты Notification Engine'ом — оба проекта могут жить рядом без коллизий |
| 2026-11-08 | Все NuGet/npm-версии пинуются точными, без `*`/`^` | Воспроизводимость CI и «собралось у меня ≠ собралось у тебя»; урок из Notification: плавающие версии подтянули net10-пакет на net8-проект |
| 2026-11-08 | Apply-модель: ВСЁ — LWW-регистр (включая `_kind`/`_z` и само существование: createSeq vs deleteSeq) | Альтернатива «patch на отсутствующий объект = ошибка» ломала бы convergence-shuffle; регистры делают apply order-agnostic по построению — идемпотентность бесплатно через `seq <= propSeq` |
| 2026-11-08 | Patch не воскрешает удалённое — только Create с seq > deleteSeq | Видимость решает пара createSeq/deleteSeq, не «есть ли props» — patch к мёртвому объекту безвредно пишет регистры и проигрывает позднему create |
| 2026-11-08 | Redis-коннект `abortConnect=false` — приложение обязано вставать без Redis | Eager Connect ронял старт/тесты; mux ретраит в фоне, health честно degraded. Тесты герметичны |
| 2026-11-08 | Room — чистая логика в Core, хаб — тонкий SignalR-адаптер | Тесты бьют комнату без TestServer/WS; точка упорядочивания (lock) тестируется Parallel.For напрямую |
| 2026-11-08 | Broadcast идёт и автору (Group, не OthersInGroup) | Автор получает серверный seq по эхо — база optimistic-reconcile в T-9; дубль на клиенте режется `seq <= lastSeq` |
| 2026-11-08 | Dedup ретрая через `_ackIndex` (clientId,clientSeq)→seq, НЕ через `_lastClientSeq` | Watermark «отбросить всё <= last» съедал бы out-of-order submits; точный индекс отвечает ровно исходным seq |
| 2026-11-08 | `IOpJournal` — sync-интерфейс, append внутри room-lock после apply | Точка упорядочивания и так сериализует все записи; async добавил бы lock-around-await и не дал бы параллелизма. Побочный плюс: snapshot не может гоняться с op — тот же лок |
| 2026-11-08 | Dedup-индексы пересобираются replay'ем journaled ops — ретрай переживает рестарт | Каждый op несёт clientId+clientSeq — отдельный dedup-store не нужен. Граница честная: dedup живёт ровно столько, сколько журнал (урезание+рестарт → древний ретрай = новый op) |
| 2026-11-08 | `RedisOpJournal` — fail-open: Redis-сбой → деградация до in-memory persistence | Альтернатива «фейлить Submit» превращает Redis-блип в остановку всего редактирования — хуже, чем потеря durability (которую /health уже показывает как degraded). Разрыв at-least-once задокументирован §16.1 |
| 2026-11-08 | Join с «протухшим» lastSeq (ниже базы журнала или в будущем) → snapshot + хвост с snapSeq | Хвост невозможен — ops урезаны; молчаливый пробел хуже полного среза. «Будущий» lastSeq = сервер потерял данные → честный сброс состояния |
| 2026-11-08 | Stream-id ≠ op-seq: `ReadSince` фильтрует по полю Seq после десериализации | Redis назначает ms-seq ids; mapping seq→stream-id добавил бы состояние без выигрыша на MVP-объёмах (XRANGE + фильтр в памяти) |
| 2026-11-08 | FractionalIndex: base-62 строка, `Between` рекурсией по общему префиксу; инвариант «не кончается `'0'`» | Тот же класс алгоритма, что у Figma/jitter: ordinal string compare = позиция, детерминизм = merge бесплатно. Trailing-zero — обязательное ограничение (между `a` и `a0` ключа не существует) — входы отвергаются, а не чинятся молча |
| 2026-11-08 | Heartbeat = обычный `Presence.Update`, без отдельного типа | Тот же payload раз в ~2с двигает lastSeen — проще протокол, TTL одинаков для движения и молчания |
| 2026-11-08 | Rate-limit дропает фанаут, но хранит значение и двигает lastSeen | Спамера нельзя «убить» призрачной смертью — joiner'ы должны видеть актуальный курсор; карается только раздувание broadcast'ов |
| 2026-11-08 | Два пути смерти курсора: disconnect (мгновенно) + sweeper TTL 10с / tick 2с | Disconnect не ловит зависшую вкладку с живым WS — нужен серверный TTL; TTL не ловит закрытый сокет быстро — нужен disconnect-хук |
| 2026-11-08 | Клиентская модель = полное зеркало серверной LWW-семантики (apply/restore), НЕ упрощённая | Одна семантика → один путь для server op / replay / optimistic apply; расхождение «клиент применяет иначе» — классический источник рассинхрона |
| 2026-11-08 | Renderer владеет rAF+canvas, React только монтирует; stats в React на ~10Гц | 60fps onFrame → setState = re-render storm; кадр только по dirty — нулевая работа в простое |
| 2026-11-08 | `JsonStringEnumConverter` в SignalR JsonProtocol — OpType как "Create", не 0 | Числовой enum на проводе хрупок (клиент сравнивает строки) и нечитаем в дебаге; цена — пара байт на op |
| 2026-11-08 | Стресс-объекты — `debugFill` вне журнала с ghost-id, lastSeq не трогается | Альтернатива «10k реальных ops» флудит сервер и портит демо-документ; ghost'ы — честный рендер-тест без лжи в seq-контракте |
| 2026-11-08 | Оптимистичный apply — дробный temp-seq `lastSeq+ε` (cap 0.9995), БЕЗ отката | «Неправильного» состояния не существует — есть только менее приоритетное: любой серверный seq переписывает temp. Откат был бы инверсией ops — сложность без выигрыша при LWW. Cap защищает от переполнения ε до целого (lastSeq — long на проводе) |
| 2026-11-08 | Rebase pending-ops на rejoin: re-apply + resubmit, dedup съедает долетевшие | §7: ручной merge = полный CRDT; resubmit-как-новые — MVP-стратегия Figma-модели |
| 2026-11-08 | QuadTree rebuild-on-version, НЕ инкрементальный | Движущийся объект = remove+insert по изменившемуся bbox — bookkeeping хрупче, чем пересборка ~мс на 10k. Инкремент нужен на 100k+, отложено |
| 2026-11-08 | `objects()` → вложенные регистры (objId→prop) и на клиенте, и на сервере | Плоская scan-per-object была O(objects×regs): на 10k объектов — сотни млн итераций на кадр/снапшот. Найдено при T-9, не замалчиваю |
| 2026-11-08 | Scale-out = owner-per-doc через Redis `SET NX` claim (advisory, без fencing), НЕ shared-state rooms | Любая схема «все инстансы применяют ops» теряет точку порядка — seq обязан назначать один процесс. Claim выбран вместо sticky routing (нет LB в MVP). Split-brain-окно при потере claim принято и задокументировано §21.1 |
| 2026-11-08 | Non-owner join читает журнал напрямую, без проксирования к владельцу | Ops/snapshot уже в Redis — вторая RPC-нога к владельцу добавила бы hop и каплин без новой информации |
| 2026-11-08 | Ack на non-owner = `seq=-1 "forwarded"`, реальный seq — эхо-бродкастом | Синхронное ожидание seq через inbox превратило бы pub/sub в RPC; optimistic-модель клиента и так сверяется по эху |
| 2026-11-08 | Reconnect storm: клиентский `random × min(30с, 2^n)` full jitter | Синхронные ретраи после рестарта — второй отказ по очереди; серверный join-шторм по журналу оставлен как известный риск §21.5 |
| 2026-11-08 | Path = один Create на mouseup, локальная отрисовка в процессе | Сотни точек драга в журнал = мусор и счёт ops; payload op имеет цену — точки <1.5wu отбрасываются, RDP не заведён (stretch) |
| 2026-11-08 | Presence через `doc:{id}:pres` pub/sub, fail-open локально | Закрывает §21.6 дёшево: тот же транспорт, отдельный канал. Снэпшот остаётся per-instance — полный presence-state требовал бы shared store, эфемерности это не стоит |
| 2026-11-08 | Room eviction по LastActivity + presence-count, recovery как exit-стратегия | Память без eviction растёт вечно; T-5 recovery уже даёт безопасную выгрузку — отдельный lifecycle не нужен |
| 2026-11-08 | Валидация/лимит — на транспорте (hub + OpRouter), НЕ в Room | Комната остаётся чистой (тесты бьют её без валидации); журнал не должен видеть мусор. Повтор в OpRouter — defense in depth против rogue publisher |
| 2026-11-08 | Rotate/выделение: `rot` — обычное prop + `rotatedBounds` AABB | Поворот как LWW-регистр бесплатно; точная повёрнутая геометрия для hit-test — платит сложностью за пиксели, AABB щедра но верна |
| 2026-11-08 | Полная дорожная карта канвы — `docs/roadmap.md` | Разросшиеся тикеты теряли «куда едем»: одна страница ✅/🚧/⬜ по областям + список сознательных отказов |
| 2026-11-09 | Inline-редактирование текста — DOM-overlay, keystrokes = applyLocal, один Patch на commit | Построчная отправка каждого кейстрока = op-шторм на журнал и rate-limit; локальный apply бесплатен и LWW-сходим — удалённый клиент видит текст на commit'е |
| 2026-11-09 | Лимиты text/points вынесены из Create-ветки в ValidateProps | Бот поймал: Patch с 5KB текстом принимался — проверки сидели только в Create. Единая точка = меньше поверхности для обхода |
| 2026-11-09 | e2e-бот — два SignalR-клиента из Node 24 (native fetch/WS), без новых зависимостей | Покрывает контракт, который юнит-тесты не видят: реальный fanout, дедуп-ребродкаст, rate-limit на проводе, presence, rejoin-tail |
| 2026-11-10 | Undo/redo — компенсирующие ops, НЕ откат журнала | Журнал append-only и общий для всех клиентов: Ctrl+Z шлёт обратный op на проводе (1 undo-запись на жест), история остаётся монотонной — время не течёт назад даже для одного пользователя |
| 2026-11-10 | Аудит-история = tail журнала (`/ops`), НЕ time-travel | Streams ограничены MAXLEN, снапшоты — точка восстановления; честная формулировка вместо обещания произвольного ревайнда |
| 2026-11-10 | Групповые трансформы — union-box геометрия + per-object Patch | Нет parent-child схемы в модели (это отдельный L-тикет): multi-select это набор id, жест генерирует обычные Patch-и — LWW и undo конвейер не меняются |
| 2026-11-10 | Rotate-ручка — 9-я точка над top-edge вместо только Shift+BR | Жест был неоткрываем (только по знанию хоткея); точка едет с rot объекта и остаётся "сверху". Совместимость: Shift+BR сохранён |
| 2026-11-10 | Lock — UX-гейт на клиенте, НЕ permission | `locked` — обычный prop; hitTest/marquee/мутации/жесты пропускают, unlock через layers-панель. Remote-опы объект двигают — честный край, сервер lock не форсит |
| 2026-11-10 | Inspector — uncontrolled input + `key=id:k:v` | Controlled input воевал бы с wire-echo; v в key перемонтирует на remote-правке (первый вариант показывал протухшие числа навсегда — поймал и починил) |
| 2026-11-10 | Auth stage 1: Redis-сессии `sess:{token}` вместо JWT | Серверный токен отзывается DELETE'ом — JWT без revocation-list не отозвать, а с revocation теряет его единственное преимущество. Sliding TTL 7d. BCrypt для паролей — единственная оправданная зависимость (password-hash нельзя писать самим) |
| 2026-11-10 | Presence-имя резолвится на сервере из токена, self-claimed игнорируется | Self-claimed имя спуфабельно одной строкой в devtools — бот проверяет: шлёт name:'hacker', комната видит login. UID/login кэш в Context.Items — но это значит logout не рвёт живой сокет: дыра, зафиксирована к stage 2 (per-op пересмотр) |
| 2026-11-10 | Токен на WS: access_token query ИЛИ Authorization-header — читаем оба | Браузерный SignalR не может ставить хедеры на WS-upgrade (шлёт query), Node-клиент может (шлёт header). Query-вариант оставляет токен в access-логах прокси — принятый trade-off браузерного WS, TLS+TTL |
| 2026-11-10 | Owned-док создаётся только явным POST /docs; implicit-join unowned = legacy-open, first-claim отклонён | «Первый залогиненный забирает док» = кража дока у анонимных редакторов. Явное создание — единственный честный способ получить owner; unowned-доки остаются открытыми (компромисс зафиксирован) |
| 2026-11-10 | Роли в Redis-хеше doc:{id}:members, НЕ в документ-props | Patch по LWW-регистру может писать любой editor — положи роль туда, и повышение себя = один op. Членство — отдельный store вне doc-модели |
| 2026-11-10 | SubmitOp перепроверяет роль на каждом op, без кэша | Кэш роли в Context.Items сделал бы revoke липким на живом сокете — та самая дыра, ради которой всё затевалось. Цена — 1-2 Redis-чтения на op; принято до профиля нагрузки |
