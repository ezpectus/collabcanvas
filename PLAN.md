# PLAN — журнал решений CollabCanvas

Каждая нетривиальная дизайн-развилка — строка в журнале: что
решили, варианты, почему. Пишет Devin, юзер оспаривает.

| Дата | Решение | Варианты и причина выбора |
| --- | --- | --- |
| 2026-11-07 | Модель синхронизации: упрощённый CRDT — LWW-регистр на свойство объекта, порядок задаёт центральный сервер (seq). НЕ OT, НЕ полный CRDT. | По образцу реальной Figma: центральный сервер уже видит все записи → timestamp/векторные часы избыточны; «last» = последний дошедший до сервера. OT не нужен — нет инвариантов трансформации текста. Полный CRDT — избыточен, т.к. нет peer-to-peer merge без сервера |
| 2026-11-07 | Порядок детей (z-order/tree order) — fractional indexing (дроби между соседями), НЕ float64 | По образцу Figma: среднее между ключами; float64 исчерпывается после ~50 вставок на одно место → строка/дробь без потери точности |
| 2026-11-07 | Разделение каналов: ops (персистентные, журнал) vs presence (эфемерный, TTL) | Presence в журнале = мусор и раздувание replay; курсор живёт секунды — ему нужен heartbeat+expiry, не durable log |
| 2026-11-07 | Комната = упорядоченный op-стрим на документ; состояние в памяти + журнал + снапшоты | Figma-модель: один процесс-владелец на документ → точка упорядочивания бесплатная. Scale-out (pub/sub) — отдельной стадией T-10, там своя точка |
| 2026-11-07 | Backend — .NET (net8.0 сейчас; net10 при установке SDK). SignalR для WS | Юзер уже знает стек из Notification Engine — ревью на знакомом языке честнее. Node.js-альтернатива из спеки отклонена: фронт и так TS |
